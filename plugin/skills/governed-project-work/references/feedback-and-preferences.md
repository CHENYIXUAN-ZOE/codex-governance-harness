# Feedback and preference retention

Use the global independent-judgment and learning rules. These are storage decisions, not a requirement to document every conversation.

| Feedback | Appropriate action |
|---|---|
| A question challenges the recommendation | Recheck the relevant facts and assumptions. Explain why the recommendation holds or what evidence changes it. A question alone is not a new project decision. |
| The user supplies a corrected fact | Accept or verify it as appropriate, fix affected work, and update an existing project source if it is durable. Do not keep a known mistake to appear independent. |
| The user makes an informed product or style choice | Follow the choice within scope; distinguish it from a claim that the alternative was factually wrong. |
| A durable project fact or requirement | Store it in the project's existing authority as part of authorized project work. If no home exists, add the smallest relevant instruction or link, not a new memory tree. |
| A correction revealing a low-risk working preference | Use `$learn-user-preferences` to retain a scoped candidate; repeated independent feedback can strengthen it under the authorized learning mechanism. Do not treat an inference as an explicit instruction. |
| An explicit request to remember a working preference | Use the preference store with the stated project or global scope. Do not rewrite installed governance or its cache for each new preference. |
| A one-off task choice, permission, or sensitive personal attribute | Do not turn it into a standing preference. Apply current task instructions only; safeguards and authority are not learned away. |

For a durable entry, retain its scope, brief evidence, confidence, and applicability. Update a superseded entry. Keep secrets, raw conversations, and transient execution details out of preference files. If the learning skill is unavailable, apply feedback now and report the persistence limitation; do not improvise a second global store.

Before the next related action, read the relevant entry and check it against current instructions and project facts. Briefly report a saved correction and its location. If no durable write occurred, do not say it will be remembered across tasks.
