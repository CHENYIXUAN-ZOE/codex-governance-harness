# Audit rubric

## Authority

- Does each concern have one current authority?
- Do instructions, Skills, config, and project facts have clear boundaries?
- Are conflicts surfaced and resolved explicitly?

## Weight

- Is always-loaded guidance concise?
- Are detailed variants progressively disclosed?
- Are unused templates, references, or empty governance files present?

## Correctness and evidence

- Are completion claims tied to executable or inspectable evidence?
- Can high-impact work identify authorization, rollback, and stop conditions?
- Do commands and paths still exist?

## Evolution

- Are model- or tool-specific assumptions isolated from invariants?
- Are changes versioned and reversible?
- Is there a representative evaluation or real friction supporting each heavy control?

## Installation

- Does installation preserve unrelated configuration?
- Are dry-run, backup, status, rollback, and uninstall defined?
- Can tests run against an isolated home without touching live state?

## Recovery

- Can a new task find current project state without chat history?
- Can an interrupted task leave a clean state and precise next step?
