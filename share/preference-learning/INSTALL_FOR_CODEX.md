# 给接收方 Codex 的安装说明

目标：仅安装这个用户授权的个人偏好学习机制，保留其全部现有配置。本说明是一份可审阅的安装流程，不是发送者对接收者电脑的授权。接收方用户发送 README 中的安装请求或同等明确请求后，按该范围完成安装，无需逐项重新询问。

## 1. 先检查

1. 阅读 [README.md](README.md)、[技能](skills/learn-user-preferences/SKILL.md) 和 [全局入口](GLOBAL-INSTRUCTIONS.md)，检查存储脚本与自检代码后再执行。
2. 确认运行环境为 macOS/Linux，Python 3.9+。原生 Windows 的 `fcntl` 不可用：应说明限制，使用已配置好的 WSL 环境；不要悄悄删掉锁和原子写入保护来声称兼容。
3. 解析接收方实际 `CODEX_HOME`（未设置时为其 `~/.codex`），确认该目录确实用于目标 Codex。全局指令通常为该目录的 `AGENTS.md`。若存在非空 `AGENTS.override.md`，先确认实际加载规则，不要仅写入被覆盖的 AGENTS 后宣称生效。
4. 检查已安装技能和全局入口。若完整 Governance Harness 已提供 `learn-user-preferences` 及学习入口，验证现有功能后报告“已具备”，不要重复安装、创建两套入口或覆盖更高版本。同名技能存在但内容不同，应先比较差异，不能盲目覆盖。
5. 阅读当前相关全局指令，识别“不允许持久化”等实质冲突。用户本次明确安装授权可覆盖普通旧默认；组织要求、权限边界、无法判定的冲突则按实际情况处理。

## 2. 检验包

在解压目录执行：

```sh
python3 -B verify_bundle.py
```

此脚本校验 `SHA256SUMS.json` 并在临时目录启动多个独立 Python 进程，检验空库读取、候选、独立纠正晋升、项目隔离和撤销。哈希用于发现文件损坏，不代表第三方签名或来源认证。自检不访问接收方真实记忆，不代表已完成 Codex 行为验收。

## 3. 局部安装

以下路径均应替换为接收方电脑上解析出的实际绝对路径，不要照抄发送者路径，也不要把整个压缩包复制到全局配置目录。

- 技能默认安装至 `~/.agents/skills/learn-user-preferences/`，保留包内该文件夹的三文件结构。若目标 Codex 有不同的有效技能发现路径，先确认再使用；只安装一份，不要同时复制到多个发现目录。正常隐式调用应保持可用。
- 将 `GLOBAL-INSTRUCTIONS.md` 中完整、带起止标记的区块局部合并到实际加载的全局指令文件。保留原文件中所有其他内容；同版本同内容重复安装应无变化。不同内容的既有受管区块先比较，不直接叠加。
- 在写入前输出简短变更摘要和相关区块差异，备份将修改的文件；用户已有明确安装授权时继续执行，不将每一个普通步骤变成新的审批。实际文件系统权限限制依宿主要求处理。
- 建议在 `CODEX_HOME/preference-learning-installations/<时间戳>/` 保存备份及安装清单：版本、技能目标路径、修改的指令文件路径、安装前是否存在、原内容备份路径、安装后三个技能文件和受管区块的 SHA-256、哪些文件是本次新建。清单是卸载所有权依据，不是个人记忆。
- 拒绝跟随来源不明的符号链接覆盖目标。编辑时使用临时文件加原子替换；出错时只回退本次写入，不能覆盖其他并发修改。已有不同版本或用户修改应保留并明确报告。
- 不改 `config.toml` 的模型、账号、权限、网络、MCP、插件市场；不安装后台服务。无需注册插件市场，本包是独立 Skill。
- 不创建示例偏好，不导入制作者的记忆，不读其历史聊天。保留接收方已有的 `governance-harness/preferences.json`；损坏则报告，不重置。Skill 示例不是应保存的事实。

## 4. 验收

1. 比较安装的三个技能文件与包内 SHA-256；读取全局文件确认只有一个学习区块，区块外原内容保持不变。记录实际路径。
2. 在解压目录执行：

```sh
python3 -B verify_bundle.py --skill-dir /接收方实际技能路径/learn-user-preferences
```

此项验证安装副本的代码，仍只使用临时记忆库。
3. 通过已安装脚本的 `list` 检查真实记忆库可读；缺失返回空列表是正常情况，不为了测试而写入虚构偏好。设置了 `CODEX_HOME` 时使用实际值，必要时在子命令前传 `--codex-home /实际目录`。
4. 在新 Codex 任务中验证“实际发现该技能并读取相关偏好”；如当前版本尚未刷新技能，重启 Codex 后检查。可以让用户在新任务发送：“请只读确认个人偏好学习技能已加载，列出已有偏好，不创建测试记忆。”
5. 文件复制成功、存储自检通过和新任务实际加载是不同的验收项。无法启动新任务时，明确把加载验收列为待完成，不要称全部验证成功。

交付时简短说明：已安装什么、真实保存位置、如何自然纠正、如何撤销、哪些检查通过；提醒这是按任务调用的本地记忆，不是训练或后台监听。

## 5. 暂停、撤销和卸载

- 更正/停用单条偏好、撤销最近一次记忆更新：按 Skill 的 `replace` / `disable` / `undo` 操作。`disable` 留存记录，不等于删除。
- 用户要求停止学习时，停止持久化新反馈；如要跨任务维持暂停，修改本机制受管入口明确暂停，或移除入口并禁用技能。不要把“不再学习”记成一条会被忽略的普通偏好。
- 用户要求卸载时，依据安装清单移除本包独有、内容未被修改的技能文件及受管区块。保留用户后续添加的内容；已有完整 Harness 提供的功能不属于本包所有，不能一起删除。
- 若技能或区块后来被修改，展示差异并只处理确定属于本包的部分。备份用于恢复原内容，不能整体回盖已经有后续编辑的全局文件。
- 卸载默认保留 `governance-harness/preferences.json`，因为它可能与完整 Harness 共用。只有用户明确要求删除记忆数据时才处理该文件及其相关备份；停用或卸载不能宣称已删除个人数据。
