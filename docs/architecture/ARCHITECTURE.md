# 架构说明

## 目标

建立一套“全局兜底、项目定制、按风险升级、可持续演进”的个人 Codex 治理系统。

## 两层模型

### 全局 Harness

全局层提供：

- 少量长期不变量。
- Lite、Standard、Assured 路由。
- 聚焦治理 Skill。
- 项目 Harness 的初始化、审计和演进能力。
- 安装、验证和回退机制。

全局层不保存具体项目事实，也不规定所有项目必须采用同一目录或流程。

全局发布由两个独立组件组成：

- `global/AGENTS.md`：以版本化受管区块合并进 `CODEX_HOME/AGENTS.md`；
- `plugin/`：仅包含运行时所需文件，通过本地 marketplace 和 Codex CLI 安装。

维护仓库中的 Git 历史、文档、测试和评测不会进入 Plugin 安装缓存。

### 项目级 Harness

项目层提供：

- 目标、范围和项目类型。
- 权威事实来源的映射。
- 项目特有约束和完成标准。
- 必要的状态、决策、风险与验证入口。

项目层优先适配已有文档、测试和工作流；只有出现真实缺口时才增加治理物件。

### 项目契约

Standard 和 Assured 项目使用 `.harness/project.json` 作为轻量、版本化的机器契约。契约只包含：

- schema 与 Harness 版本；
- 治理强度和可组合领域模块；
- 项目、架构、状态、决策、风险和计划的权威来源指针；
- 默认验证命令。

契约采用 JSON，以便核心初始化与审计工具仅依赖 Python 标准库。Lite 不创建持久契约；Assured 必须声明风险权威来源和至少一个验证命令。

## 实现分层

```text
用户当前目标与授权
  ↓
global/AGENTS.md        最小治理内核与路由
  ↓
skills/                 按需加载的可复用工作流
  ↓
项目 AGENTS / 契约      项目事实地图与局部规则
  ↓
测试 / CI / Hooks       确定性验证与强制边界
```

## 权威来源原则

- 一个主题只有一个当前权威来源。
- 全局内核只定义跨项目行为，不复制项目事实。
- 项目契约只保存指针和少量机器可读元数据，不复制完整文档。
- 外部系统中的实时事实由相应连接器或 MCP 提供；需要长期复现的决策应进入项目可版本化来源。
- Memory 和聊天可以辅助召回，但不承担强制规则或当前状态的唯一权威。

## 风险与权限正交

治理强度描述“需要多少计划、证据和审查”；权限配置描述“技术上允许访问什么”。Assured 模式不会自动获得更高权限，反而通常需要更窄的边界和更明确的审批。

## 渐进加载

1. 始终加载短小的全局和项目 `AGENTS.md`。
2. 只有 Standard 或 Assured 工作才加载治理执行 Skill。
3. Skill 只在需要时读取对应 reference。
4. 项目事实按权威映射定向读取。
5. 不默认扫描全部文档或加载全部模板。

## 演进

- 原则稳定，机制可换。
- 新能力不会自动触发重写。
- 重复摩擦或新能力先形成证据。
- 通过基线、单变量修改和对照评测判断组件是否承重。
- 核心不变量由用户批准；普通机制按版本和变更记录演进。

## 安装与回退

安装管理器默认 dry-run，并显示全局规则的精确 diff。显式应用时：

1. 记录版本、目标、原始规则和本次所有权。
2. 原子写入全局受管区块。
3. 通过 Codex CLI 注册 marketplace 并安装 Plugin。
4. 写入 active state 和事务记录。

任何中途失败都会尝试逆序回滚。卸载只恢复或移除受管区块，并且只移除本次安装新增的 Plugin 与 marketplace；区块之外的后续用户编辑保持不变。修改过的受管区块会导致卸载拒绝，而不是猜测性覆盖。
