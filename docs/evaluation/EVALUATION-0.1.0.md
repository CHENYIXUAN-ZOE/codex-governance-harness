# 0.1.0 评测记录

## 目的

验证全局治理内核与四个按需 Skill 是否改善治理强度、Skill 路由、持久治理物件和高影响暂停点的判断，同时量化常驻上下文成本。

## 方法

- 12 个只读分类案例，覆盖 Lite、Standard、Assured、四个治理 Skill、负触发和治理物件控制。
- 每个案例比较 4 个精确字段。
- 基线使用临时空白 `CODEX_HOME`。
- Treatment 在另一临时 `CODEX_HOME` 中通过真实 Codex CLI 安装。
- 所有调用使用 ephemeral 会话和 read-only sandbox。
- Treatment 完整集独立重复一次。

环境：`codex-cli 0.146.0-alpha.3.1`，默认模型，2026-07-30。

## 结果

| 指标 | 基线 | Treatment 1 | Treatment 2 |
|---|---:|---:|---:|
| 完全正确案例 | 9/12 | 12/12 | 12/12 |
| 字段准确率 | 85.4% | 100% | 100% |
| 平均输入 tokens | 11,842 | 13,255 | 13,266 |
| 平均输出 tokens | 139 | 98 | 101 |
| 平均推理输出 tokens | 65.5 | 21.5 | 24.5 |

相对基线，Treatment 平均增加 1,413 input tokens（11.9%），低于当前 1,800 tokens 门禁。全局常驻规则为 3,091 字节、427 词；四个 Skill 的 `SKILL.md` 共 7,923 字节，按需加载。

基线错误集中在：

- 将普通持久多文件工作过度升级为 Assured；
- 把普通项目产物误判为治理物件；
- 将只读治理审计过度升级为 Assured。

两次 Treatment 均完全通过，说明两层路由对这些边界有稳定帮助。

## 决定

- 保留 0.1.0 的全局内核与四个 Skill，不在缺少反例时为进一步减小 token 而压缩触发描述。
- 当前发布候选门禁：Treatment 完整集 100%，平均输入增量不超过 1,800 tokens。
- 后续版本必须使用相同案例回归；改变模型时应显式固定模型并重新建立基线。

## 局限

- 当前只评估路由，不代表完整任务执行质量。
- 每轮每案例只有一个样本，仍需真实项目 canary。
- “默认模型”会随环境变化；发布比较需要显式模型标识。

机器可读摘要见 `evals/results/0.1.0-summary.json`。
