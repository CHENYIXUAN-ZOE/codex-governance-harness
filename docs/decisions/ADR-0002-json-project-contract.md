# ADR-0002：项目契约采用版本化 JSON

- 状态：Accepted
- 日期：2026-07-30

## 背景

项目级 Harness 需要一个稳定的机器接口，用来声明治理强度、领域模块、权威事实来源和验证入口。该接口必须易于校验、适合版本控制，并尽量减少在不同机器和未来 Codex 版本上的运行依赖。

## 决策

Standard 和 Assured 项目使用 `.harness/project.json`：

1. `schema_version` 管理契约格式兼容性。
2. `harness_version` 记录生成契约的 Harness 版本。
3. `authority` 只保存事实来源指针，不复制事实内容。
4. `verification.default` 保存可执行验证入口。
5. JSON Schema 提供标准结构定义，Python 标准库验证器提供运行时安全与路径检查。
6. Lite 不创建持久契约。
7. Assured 必须声明风险权威来源和至少一个验证命令。

初始化默认只展示计划；只有显式 `--apply` 才创建缺失文件。现有契约不一致时拒绝覆盖。

## 后果

正面：

- 核心工具不依赖 YAML 解析器或项目技术栈。
- 输出确定、易于 diff，并可由多种语言和 CI 工具消费。
- schema、工具和契约版本可以独立演进。
- 权威来源仍留在项目已有文档或外部系统中。

代价：

- JSON 不支持注释。
- schema 无法表达全部跨平台路径安全规则，因此运行时验证器仍是必要组成。
- 修改契约需要显式迁移流程，不能静默重写。

## 未采用

- YAML：可读性较好，但会引入解析器依赖和更多方言差异。
- 仅使用 `AGENTS.md`：适合人类指导，不足以作为稳定机器接口。
- 固定项目目录树：会复制事实并增加已有项目迁移成本。
