# ADR-0003：采用精简包与事务化本地安装

- 状态：Accepted
- 日期：2026-07-30

## 背景

全局 Harness 同时包含一个常驻 `AGENTS.md` 内核和一个按需加载的 Plugin。初次隔离演练证明，若直接把维护仓库根作为 Plugin 源，Codex 会把 Git 历史、测试、文档和本地缓存一起复制到安装缓存。直接编辑 `config.toml` 还会绕过官方 Plugin 生命周期，并扩大配置冲突与回退风险。

## 决策

1. 维护仓库与可安装运行包分离。
2. `plugin/` 只包含 manifest、Skills、共享库、schema、模板和版本文件。
3. 仓库通过 `.agents/plugins/marketplace.json` 暴露本地 Plugin。
4. Plugin 注册、安装和移除调用 Codex CLI，不直接修改 `config.toml` 或缓存。
5. 全局内核作为带版本标记的受管区块合并进 `CODEX_HOME/AGENTS.md`。
6. 安装和移除默认 dry-run；显式应用才改变状态。
7. 每次安装记录组件所有权、原始规则、事务和 active state。
8. 失败时逆序回滚；卸载只移除本次拥有的组件，并保留区块之外的用户编辑。
9. 受管区块、版本或来源发生未解释漂移时拒绝猜测性修复。

## 后果

正面：

- 安装缓存体积和暴露面可预测。
- 使用 Codex 官方 marketplace 与 Plugin 状态模型。
- 现有全局规则和配置不会被整体覆盖。
- 失败、回退和卸载行为可测试、可审计。
- 源码仓库可以继续包含丰富文档与评测，而不增加运行包重量。

代价：

- 本地 marketplace 记录源码仓库绝对路径，移动仓库后需要重新注册。
- 0.1.0 不支持原地跨版本升级；版本不同或状态漂移时先回退，再用新源码安装。
- 事务回滚仍依赖 Codex CLI 可用；若 CLI 自身失败，doctor 和事务记录用于人工恢复。

## 未采用

- 直接复制整个仓库：会安装无关和潜在敏感内容。
- 直接写 `config.toml` 与 Plugin 缓存：容易破坏其他配置，且偏离官方生命周期。
- 无状态复制全局规则：无法区分用户内容与 Harness 内容，也无法安全卸载。
