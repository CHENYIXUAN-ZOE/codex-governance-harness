# ADR-0004：有范围和证据的偏好学习

- 状态：Accepted；2026-09-20 用户授权修改实际全局配置，并明确要求从重复纠正中学习，而非逐条维护偏好规则。
- 日期：2026-09-20
- 版本：0.2.0

## 证据与目标

用户报告反问容易引起无依据的附和，反复纠正后类似问题仍再出现；随后明确反问只是例子，目标是自动识别和记住个人偏好。0.1.0 只有“重复失败后改进”的原则，没有偏好检索、证据积累、更新、撤销的执行入口。

当前官方模型指导建议收窄技能触发、按任务读上下文、限制重复确认与过度验证：

- https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra
- https://developers.openai.com/api/docs/guides/latest-model

全局内核保持模型中立，不固定未来的模型、推理强度或工具。

## 决策

1. 全局内核保存判断和学习机制；可变的个人偏好不逐条追加到 AGENTS。
2. 新增 `learn-user-preferences`，运行时数据保存在 `CODEX_HOME/governance-harness/preferences.json`。全局偏好与精确项目范围分开；项目事实仍留在项目权威来源。
3. 当前用户授权允许从有意义的纠正推断低风险交流和工作方式偏好，无需每次重新确认。候选是可修订的软默认，不是用户明确指令。
4. 两个不同上下文中的纠正可支持晋升；事件 ID 去重，同一轮反复争论不算独立证据。明确长期表达可直接记录为 explicit。不伪造历史证据。
5. 新任务先检索相关记录，当前指令和项目事实优先。相反反馈必须可修正、替换、停用；最近一次存储更新可撤销。实际写入成功才称已记住。
6. 不从偏好推导授权、权限提升或降低验证安全要求，不保存秘密、敏感个人属性或全文聊天。模式拦截只能辅助，不能替代语义判断和宿主权限控制。
7. 不安装后台监听、全局 Hooks、MCP、云存储或向量库。自动化依赖 Codex 按已加载规则调用技能，不能保证所有未来任务必然触发。
8. 用户授权的是本机制和本次部署，不是自动修改核心治理。偏好存储更新与治理源码发布是不同操作；每次核心机制升级仍须版本化、验证和明确授权。

## 同步精简

收窄 Standard/Assured 到实际协调或后果；已有授权继续有效；只阻塞依赖缺失决策的动作；足够验证后交付。JSON 项目契约改为可选，修复未采用/损坏混淆。

这些是分别可测的改动；不将打包发布的一组改动当成单变量性能实验。偏好正确性通过隔离状态转换、真实输出和独立场景验证；旧 0.1.0 的分类分数不外推为新版本收益。

## 发布与回退

沿用 ADR-0003 的两阶段安装。新源码只允许在旧插件缺席且 active state 的来源、版本、块哈希一致时移除旧受管规则；旧插件仍安装时需旧源码完成旧版回退。先备份当前全局状态，展示差异，再受控替换。失败恢复安装前状态；偏好数据独立保留，不随插件卸载删除。

## 验证边界

候选门槛并非统计置信保证；低风险偏好的自动推断仍可能错。必须能查看、更正与遗忘，并在真实任务中观察误用和用户干预。缺少写权限或技能不可用时说明未持久化，不承诺跨会话记忆。
