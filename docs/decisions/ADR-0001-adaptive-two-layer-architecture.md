# ADR-0001：采用自适应两层治理架构

- 状态：Accepted for source development
- 日期：2026-07-30

## 背景

用户希望所有项目拥有全局 Harness 兜底，同时允许具体项目根据类型、目标和风险定制。系统还必须避免规则过重，并能随模型能力演进。

## 决策

采用：

1. 极薄的全局治理内核。
2. 插件化、聚焦、渐进加载的治理 Skills。
3. 适配已有事实来源的项目契约。
4. Lite、Standard、Assured 三档治理强度。
5. 机械验证优先于重复文字提醒。
6. 评测、版本和回退驱动的演进流程。

源码仓库、全局安装和项目初始化保持分离。

## 后果

正面：

- 简单任务不会承担完整治理成本。
- 项目能够保留自己的结构和事实来源。
- 全局规则可版本化、审计和回退。
- 未来可以删除被模型能力替代的脚手架。

代价：

- 需要维护安装和兼容性测试。
- 路由错误可能造成治理不足或过度治理。
- 项目契约与真实状态可能漂移，需要审计。

## 未采用

- 单一大型全局提示词：上下文成本和腐化风险过高。
- 所有项目统一重型模板：迁移成本高且产生空治理物件。
- 默认启用全局 Hooks 或 MCP：第一阶段收益尚无证据，扩大了故障面。
- 依赖 Memory 保存强制规则：无法作为稳定权威来源。
